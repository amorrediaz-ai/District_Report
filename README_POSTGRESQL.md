# District Report: PostgreSQL на Render

В этой версии пользователи, хеши паролей, обращения, лайки и фотографии сохраняются
в PostgreSQL. Локальные `main.db` и `uploads/` больше не используются сайтом.
Страницы и адреса сайта остаются прежними.

## Файлы

Нужно применить все изменения этой ветки, включая `app.py`, новый `database.py`
и `requirements.txt`. Замены одного `app.py` недостаточно.
`migrate_sqlite.py` нужен только для переноса старых данных, а `tests/` — для проверки.

## Запуск на Render с новой пустой базой

1. Открой свою PostgreSQL на Render → Connect и скопируй **Internal Database URL**.
   Web Service и база должны находиться в одном аккаунте и регионе.
2. В Web Service → Environment добавь:

   | Переменная | Значение |
   |---|---|
   | `DATABASE_URL` | Internal Database URL твоей PostgreSQL |
   | `SECRET_KEY` | Постоянная случайная строка, не менее 32 символов |
   | `ADMIN_EMAIL` | Email для входа администратором |
   | `ADMIN_PASSWORD` | Пароль администратора, не менее 12 символов |

   Сгенерировать секрет локально:

   ```bash
   python -c "import secrets; print(secrets.token_hex(32))"
   ```

   Не меняй `SECRET_KEY` при каждом запуске: это завершит действующие сессии.
   Не добавляй URL с паролем и секреты в GitHub, скриншоты или сообщения.

3. Установи команды:

   **Build Command**

   ```bash
   pip install -r requirements.txt
   ```

   **Start Command**

   ```bash
   gunicorn app:app --workers 1 --bind 0.0.0.0:$PORT
   ```

4. Примени изменения ветки в `main` и запусти Deploy. При наличии Auto-Deploy
   Render начнёт развёртывание после обновления ветки.
5. Открой сайт, создай пользователя и обращение с фото, поставь лайк.
   Повтори проверку после Restart Service: данные должны остаться.

При запуске создаются недостающие таблицы; существующие записи не удаляются.
Администратор создаётся только если в базе ещё нет администратора.
Переменные `ADMIN_EMAIL` / `ADMIN_PASSWORD` не меняют пароль существующего аккаунта.
HTTPS-cookie автоматически включаются в среде Render (`RENDER=true`).

## Перенос старой SQLite базы — необязательный шаг

Если нужны старые пользователи и обращения, выполни перенос **до первого запуска
нового сайта**, пока PostgreSQL пуста. Автоматического переноса при запуске нет.
Если сайт уже создал администратора, импорт откажется работать, чтобы не перезаписать
аккаунты. Используй отдельную пустую базу; импорт не очищает существующую.

1. Сохрани резервную копию `main.db` и папки `uploads`. Останови запись в старый
   сайт на время переноса. Скачай эту ветку проекта на компьютер.
2. Установи Python 3.10+ и зависимости:

   ```bash
   python -m pip install -r requirements.txt
   ```

3. Для запуска **на своём компьютере** используй **External Database URL** Render.
   Разреши подключение со своего IP в настройках внешнего доступа базы, если оно ограничено.
   Чтобы не сохранять пароль базы в истории команд, в PowerShell введи URL скрыто:

   ```powershell
   $dbUrlSecure = Read-Host "External Database URL" -AsSecureString
   $env:DATABASE_URL = [System.Net.NetworkCredential]::new("", $dbUrlSecure).Password
   python migrate_sqlite.py --sqlite main.db --uploads uploads
   Remove-Item Env:DATABASE_URL
   Remove-Variable dbUrlSecure
   ```

4. После сообщения об успешном переносе включи новую версию сайта на Render,
   где `DATABASE_URL` должен содержать Internal Database URL.

Импорт сохраняет ID, имена, email, хеши паролей, права администратора, обращения,
даты, счётчики и записи лайков. Старые пароли продолжают работать.
SQLite открывается только для чтения; изменения PostgreSQL выполняются одной
транзакцией. Ошибка отменяет импорт. Повторный импорт в заполненную базу запрещён.
Анонимные лайки сохраняются, но возможность снять старый анонимный лайк зависит от
сохранения прежнего домена и cookie-сессии с прежним `SECRET_KEY`.

Для старых фото нужна именно старая папка `uploads`: одних имён в SQLite недостаточно.
Если часть файлов потеряна, обычный импорт остановится. Только если согласен перенести
обращения без отсутствующих фото, явно добавь:

```bash
python migrate_sqlite.py --sqlite main.db --uploads uploads --skip-missing-photos
```

После переноса поменяй стандартный/слабый пароль старого администратора. На компьютере
с установленными зависимостями задай External `DATABASE_URL` и постоянный `SECRET_KEY`
как переменные окружения, затем выполни (замени email на email своего администратора):

```bash
python -m flask --app app set-admin-password admin@districtreport.local
```

Новый пароль вводится скрыто дважды; в команду его добавлять не нужно.
Репозиторий содержит ранее загруженную `main.db`: `.gitignore` не удаляет уже
закоммиченный файл или его историю. После проверки переноса сохрани личную резервную
копию и отдельно убери этот файл из GitHub; не публикуй репозиторий с пользовательской базой.

## Хранение и ограничения

- Новые фотографии до 5 МБ записываются в `BYTEA` в строке обращения. Это подходит
  для небольшого учебного проекта; для большого количества фотографий лучше отдельное
  объектное хранилище. Фото занимают место в лимите PostgreSQL.
- Перезапуск Web Service не удаляет PostgreSQL. Удаление самой базы или истечение
  срока её тарифа влияет на данные: PostgreSQL не заменяет резервное копирование.
- На бесплатном тарифе Render PostgreSQL действует 30 дней и имеет лимит 1 ГБ;
  бесплатные базы не имеют встроенных резервных копий. Для длительного использования
  заранее выбери подходящий тариф и делай резервные копии через `pg_dump`.
- Подключение к удалённой PostgreSQL по умолчанию использует `sslmode=require`;
  явно заданный в URL режим сохраняется. Для локального PostgreSQL TLS необязателен.

Официальная документация:
- https://render.com/docs/postgresql-creating-connecting
- https://render.com/docs/free
- https://www.psycopg.org/psycopg3/docs/

## Проверка кода

```bash
python -m pip install -r requirements.txt pytest
```

Задай `TEST_DATABASE_URL` на тестовую PostgreSQL, затем:

```bash
python -m pytest -q tests/test_postgresql.py
```

Тесты создают отдельную случайную схему и удаляют только её. Проверяются регистрация,
вход, сохранение фото при повторном запуске приложения, фильтры, кириллический поиск,
лайки, права администратора, удаление, CSRF, миграция и откат неудачного импорта.
